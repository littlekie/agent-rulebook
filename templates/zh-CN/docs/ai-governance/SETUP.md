# 将规范接入项目

初始化只生成本地文件。模型审查、安全服务、可信证据收集、GitHub 保护规则和自动合并
均**尚未配置**。附带的 Node.js 工具需要 Node.js 22+，目标项目可以使用任意技术栈。

## 1. 整合规范与真实命令

本目录有建议稿时，将适用内容整合到已有 AGENTS.md / REVIEW.md，保留项目规范，
确认完成后删除建议稿。通过所用 Agent 支持的机制加载根规范；文件存在不证明 Agent 已加载。

活动配置位于根 `ci/commands.json` 和 `ci/quality-policy.json`。
将检查映射为项目实际命令，每个检查对应若干参数数组，例如：

```json
{
  "setup": [["npm", "ci"]],
  "unit": [["npm", "test", "--", "--runInBand"]]
}
```

上例并非完整配置，须按项目工具链修改。从项目根目录运行 worker，命令在当前工作目录执行。
业务、架构、安全检查须验证真实约束，不能用空脚本或假成功替代。不适用的检查应通过明确的
策略变更审查后调整；`null` 仍表示 UNCONFIGURED。无法由本地命令执行的平台检查需要可信适配器。

运行 `agent-rulebook doctor .` 检查本地配置缺口；它不执行命令，也不验证远程保护。
审查配置后，在合适环境中显式执行真实检查，例如 `node ci/run-check.cjs unit`。

## 2. 先接入普通 CI 与审查报告

参考 `ci/templates/github-checks.yml.example` 整合现有 CI，配置固定版本运行时后再启用工作流。
示例运行全量检查及汇总，不是可信的最终放行门禁。
在隔离 worker 中执行 PR 代码，不提供模型密钥、生产 secrets 或合并凭据。

单独选择审查服务，在独立上下文中使用 `ci/ai-review-prompt.md`。
通过真实历史或当前 PR 检查漏报、误报及上下文缺口。默认一位独立代码审查者；
存在具体安全风险时增加安全专项。CLI 本身不包含模型服务。

## 3. 自动放行前建立可信控制器

`ci/quality-gate.mjs` 只检查输入 JSON 的逻辑关系，**不认证证据来源**。
任何人都可伪造返回 eligible 的本地输入。控制器必须从待审 PR 之外的已批准版本加载
策略、检查命令、审查指令与门禁代码，核验平台身份、完整差异、检查签发者及运行版本，
从可信来源采集审查和审批。PR artifact 与作者自报成功不能直接成为可信证据。

证据绑定 repository、pr_number、head_sha、base_sha、tested_sha 与 policy_sha256。
tested_sha 是实际测试的提交；策略摘要使用已批准文件的原始字节。上下文变化使旧证据失效。
L2 审批须由有权限的独立人工针对当前上下文确认，签发前再次核验最新版本。
开发适配器时参考 evaluator 源码及测试；本工具尚未提供控制器。

保护最终必要检查并绑定预期签发者，保护策略和 workflow 变更，检查绕过权限。
只接受明确 success；缺失、跳过、过期或失败均保持待放行。
代码执行、模型审查、结果签发和合并使用各自权限边界。

合并授权由项目决定。自动化先从 L0 验证，再逐步开放 L1；L2 保留关键事项人工确认。
示例监听 merge_group，但 evaluator 只处理单 PR；合并队列还需要核验所有组成 PR 和组合
测试提交的控制器，在实现前不能宣称队列门禁已启用。

## 4. 验证实际接入

至少演练伪造结果、修改门禁代码、重命名高风险文件、差异不完整、检查跳过、模型超时、
上下文截断、新提交、基础分支变化、无权限审批及签发后新推送。
单元测试不能证明平台身份、隔离执行与竞态处理，自动放行前记录对应集成验证。
数据迁移还需数据恢复方案。

`quality-gate.mjs` 接受 --policy、--context 和 --evidence 路径。
退出码 0 表示给定证据满足策略、1 表示 hold、2 表示输入无效，0 不授予合并权限。
生成的工具与模板按本目录 LICENSE 提供。
